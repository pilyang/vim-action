# AX Visual은 세션 단위 경로 고정 + `VisualAnchorTracker` 공유 — 무상태 폴백 금지

## 결정

- **세션 단위 경로 고정**: Visual 세션의 실행 경로는 진입(`beginSelection`) 시점에 정한다 — 진입 증명 성공이면 세션 전체 AX(범위 쓰기), 실패면 세션 전체 keyboard(PR-C1의 기존 재앵커 기계 그대로). **세션 중간의 증명·읽기 실패는 그 액션만 정직한 스킵**이다 — keyboard 무상태 시퀀스로의 폴백은 금지한다.
- **`VisualAnchorTracker`를 두 경로가 공유**한다(AX 전용 경량 상태 기각). AX 경로는 채울 수 있는 필드를 **전부 정확값으로** 채운다 — `anchor`·wise·`originalCaret`(정확 — 열 근사·상한 32 불필요)은 물론 keyboard 실행 아티팩트인 `side`·`pinnedEnd`까지(`side = anchor < focus ? .left : .right`, `pinnedEnd` = 앵커 쪽 끝). `focusLineDistance`의 AX 대응물은 포커스 오프셋 정확값이다.
- **자가 검증은 AX 경로에서도 유지**한다(단측 — 앵커 쪽 끝 + pid + 비어 있지 않음). 비용은 실질 0이다 — 새 범위 계산에 어차피 매 액션 선택을 읽어야 하고 검증은 그 읽기에 비교를 얹는 것뿐. AX는 양 끝을 다 쓰므로 원리상 양단 검증이 가능하지만, 앱이 범위를 정규화·클램프하면 헛폐기가 상시가 되므로 **D1은 단측 유지 + 포커스 끝 불일치는 DEBUG 로그만** — 도그푸딩이 "정규화 앱 없음"을 보이면 승격한다(`provenViewport` 방법론).
- **상태 갱신 시점**: keyboard의 "게시 확정(`.groups`) 시"의 AX 등가는 **범위 쓰기가 `.success`를 돌려준 시점**이다 — 게시(배달만 걸림)보다 강한 확정이라, PR-C1 보강 ⓒ가 막았던 "게시 전 적용 후 드롭" 창이 AX에는 구조적으로 없다.

## 배경·근거 (왜)

- **무상태 폴백 금지가 이 결정의 뿌리다.** keyboard 경로에서 읽기 실패 폴백이 안전한 것은 앱의 앵커가 앱 자신의 키 입력으로 서 있어 자기 일관적이기 때문이다. AX가 `AXSelectedTextRange`를 써 넣은 뒤에는 **앱이 어느 끝을 포커스로 보는지 미정의**(범위에 방향이 없다)라, 무상태 `Shift-→`가 앵커를 넘어 반대쪽으로 자랄 수 있고 이어지는 `d`가 엉뚱한 텍스트를 지운다 — 강등이 아니라 파괴 방향 동전 던지기다. 이는 [쓰기 후 폴백 금지](20260808_ax-write-failure-whitelist-no-fallback.md)를 Visual 축에서 독립적으로 뒷받침한다.
- **세션 고정이 액션 단위 선택보다 나은 이유**: 세션 중간에 경로가 오가면 "AX 앱인데 가끔 Visual이 현행처럼 군다"는 비결정성이 되고, 위임된 확장은 앵커 상태 없는 무상태 시퀀스라 위 위험과 같은 축이다. 진입 시점 고정이면 한 세션 안 동작이 일관되고, keyboard 고정 세션은 검증된 기존 코드가 그대로 돈다.
- **트래커 공유의 결정 논거는 인수인계가 공짜라는 것**: `anchor`(논리 앵커 절대 오프셋)는 전략 전환의 충분통계다 — 어느 경로든 이번 액션의 읽기 `[l, r)`과 `anchor`만으로 나머지(포커스·side·pinnedEnd)를 역산할 수 있어, `per_element`(PR-E)·auto 프로브로 한 앱 안에서 전략이 갈리는 미래에 새 코드 0줄로 세션이 이어진다. 분리하면 소유자가 갈라져 전환 순간 상태를 옮기거나 버려야 하고, 버리면 "전략이 섞일수록 Visual이 자주 죽는다"가 된다. 마우스 클릭이 두 상태 중 하나만 죽이는 조합도 원리적으로 없어진다.
- AX가 keyboard 전용 필드까지 채우는 단서가 공유를 완성한다 — 비워 두면 전략이 keyboard로 넘어가는 순간 낡은 `pinnedEnd`로 검증이 실패해 세션이 죽는다(안전 방향이지만 아깝다). AX는 두 끝을 다 알아 채우는 비용이 0이다.
- 세션 중 위임 액션(`Ctrl-d`·`u`·`p`)은 선택을 파괴할 수 있으므로 자가 검증은 AX에서도 여전히 필요하다 — "AX가 정확히 아니까 상태 단순화"는 side·재앵커 곡예의 소멸이지 검증의 소멸이 아니다.

## 검토한 대안

- **액션 단위 스킵만(세션 고정 없음)**: 가장 단순하나 위 비결정성. 세션 고정은 이 안을 "중간 실패" 케이스로 포함하는 상위 구조라 추가 비용이 작다.
- **AX 전용 경량 상태(앵커 오프셋만)**: 소유자 분열 — per_element 미래에 인수인계 코드가 필요해지고, 협력자 계약(게시 큐 단독 소유·주입 seam)을 셋으로 늘린다.
- **즉시 양단 검증**: Notion(visible 오보 실측 전례)류가 범위를 스냅하면 헛폐기 상시 — 도그푸딩 후 승격으로 이연.

향후 항목(비차단): per_element가 들어오면 pid만으로 세션 컨텍스트가 부족하다(같은 앱 두 요소 간 포커스 이동은 pid 동일) — 리졸버 캐시 세대 토큰을 상태에 실어 검증하는 확장을 PR-E에서 검토.
