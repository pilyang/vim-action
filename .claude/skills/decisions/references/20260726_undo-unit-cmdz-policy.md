# undo 단위 실측 — u=Cmd-Z 유지, 시퀀스 설계 자유

## 결정

`u`=Cmd-Z(네이티브 undo 위임)를 유지하고, M3 편집 시퀀스 설계에 **undo 쪼개짐 제약을 두지 않는다** — "선택 후 잘라내기" 형태의 다타 시퀀스가 앱 undo 히스토리에 한 단위로 남는 것이 실측으로 확인됐다. 단, **change(c 계열)는 "삭제 1단위 + 타이핑 N단위(macOS 코얼레싱)"로 나뉘는 것을 수용 엣지로 확정**한다 — Vim의 "u 한 번에 change 전체 취소"와 다르다.

## 배경·근거 (왜)

합성 편집 시퀀스(예: dd = `Cmd-←, Shift-↓, Cmd-X`)가 키스트로크별로 undo 단위를 조각내면 `u`가 "줄 삭제 취소"가 아니라 "3단계 중 1단계 취소"가 되어 시퀀스 설계 자체(최소 타수 원칙)를 다시 세워야 했다. M3 단계 0에서 후보 시퀀스를 표준 macOS 텍스트 키바인딩이 적용되는 앱들(Notion 등)에서 수동 실측:

| 시퀀스 | Cmd-Z 완전 복원 |
|---|---|
| dd (`Cmd-←, Shift-↓, Cmd-X`) | 1회 |
| dw (`Shift-Opt-→, Cmd-X`) | 1회 |
| cw (`Shift-Opt-→, Cmd-X` + 타이핑) | 2회 — 타이핑 제거 → 단어 복구. 타이핑 측은 macOS 코얼레싱 단위라 항상 전체가 한 번은 아님 |
| o (`Cmd-→, Return` + 타이핑) | 1회 |
| p (`Cmd-←, Cmd-V`) | 1회 (2회째는 앞선 잘라내기 취소 — 정상 분리) |

선택·삭제·붙여넣기는 앱이 "편집 발생 시점"(Cmd-X/V) 기준으로 undo 단위를 만들므로, 선행하는 캐럿 이동·선택 키는 단위를 오염시키지 않는다. change의 2단위 분리는 keyboard 전략에 그룹핑 수단이 없어(undo grouping API는 AX/앱 내부 영역) 수용한다 — 사용자 관점에서는 `u`를 한 번 더 누르면 되는 수준.

**동반 관찰 — 앱별 키바인딩 편차**: TextEdit 등 일부 mac 네이티브 앱에서 Opt-화살표 계열 콤보가 표준대로 동작하지 않는 경우가 관찰됐다. 키스트로크 매핑이 표준 텍스트 키바인딩을 전제하는 keyboard 전략의 원리적 한계로, 앱별 대응은 M5 AX 어댑터(또는 프로파일 per_element 재정의)의 영역이다.

## 검토한 대안

- **시퀀스 최소 타수 원칙 (쪼개짐 대비 설계 제약)**: 쪼개짐이 실증됐을 경우의 대비안이었으나 실측 결과 불필요 — 채택 안 함.
