# 앵커 무효화는 읽기 자가 검증 — 별도 신호 없음

## 결정

낡은 앵커(마우스 개입·앱 전환·앱의 비동기 처리 등)는 **전용 무효화 신호 없이, 매 Visual 액션의 읽기에서 자가 검증**으로 걸러낸다:

1. **pid 일치** — 읽기 컨텍스트의 pid가 상태 수립 시점과 다르면 폐기.
2. **앵커 쪽 끝 일치** — 읽은 선택 `[l, r)`에서 앵커 쪽 끝이 상태의 기대와 일치하는가 (`.left`면 `l == 앱 앵커`, `.right`면 `r == 앱 앵커`). 불일치면 폐기.

폐기 = 상태 삭제 + 그 액션부터 현행 무상태 시퀀스 폴백. **검증은 앵커 쪽 끝만 본다** — 포커스 쪽 끝은 모션 착지를 앱이 계산하므로 우리가 예측할 수 없고, 예측 가능한 쪽만 검증해야 헛실패가 최소가 된다.

## 배경·근거 (왜)

앵커 상태는 읽기 memo와 달리 `execute` 사이에서 **화면과 어긋날 수 있다** — 사용자가 마우스로 선택을 바꾸거나, 다른 앱을 다녀오거나, 앱이 우리 시퀀스를 아직 소화하지 못한 경우다. M5 플랜이 "무효화 조건을 설계 초입에 정하라"고 명시한 함정이다.

자가 검증을 택한 이유:

1. **원인을 가리지 않는다.** 마우스든 앱 전환이든 앱의 지연이든, 결과적으로 앵커가 어긋났다는 사실 자체를 잡는다. 신호 기반은 원인별 배선이 필요하고 마우스는 신호 자체가 없다(우리 탭은 키보드 전용 — 마우스 이벤트는 들어오지 않는다).
2. **배선이 0이다.** Visual 정확화 경로는 어차피 매 액션 선택 범위를 읽는다 — 검증은 그 읽기에 비교 두 개를 얹는 것뿐이다. 리졸버(메인/전용 큐)→게시 큐로 무효화 신호를 나르는 새 채널이 필요 없다.
3. **틀리는 방향이 안전하다.** 헛실패(예: 빠른 연타에서 앱이 직전 확장을 아직 반영하기 전에 읽음 — `CGEvent.post`는 배달만 걸고 돌아온다)의 결과는 오동작이 아니라 **현행 무상태 동작으로 강등**이다. 정확화 포기이지 파괴가 아니다 — "증명 못 하면 현행"의 보수 방향과 같다.

## 검토한 대안

- **신호 기반 무효화** (포커스/앱 전환 알림을 게시 큐로 배선): 잡는 케이스가 자가 검증의 진부분집합이다 — 전환은 다음 액션의 pid·선택 불일치로 어차피 드러나고, 같은 요소 안의 마우스 선택 변경은 신호가 아예 없다. 배선 비용만 남아 기각.
- **병행 (자가 검증 + 신호)**: 방어 겹층의 실익이 없다(위와 같은 이유). 기각.
- **마우스 이벤트 감시 탭 추가**: 무효화 하나를 위해 탭·스레드·권한 표면을 늘리는 과잉. 기각.
