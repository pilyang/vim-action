# Shift 새어 들어감 — 이벤트 flags 명시 대입으로 완결, 전역 상태 정리는 기각

- **결정일**: 2026-07-26

## 결정

"Shift 새어 들어감" 우려(`$`·`G`·`^`·`A`는 사용자가 Shift를 물리로 누른 상태에서 합성 Cmd/Opt 조합이 게시되므로 이동이 선택으로 변질될 수 있다)는 **어댑터의 이벤트 flags 명시 대입(`event.flags = stroke.flags`)을 채택된 완결 형태로 확정**하고 종결한다. 게시 전 전역 modifier 상태 정리(합성 flags-changed 이벤트로 물리 Shift를 떼었다 붙이기)는 도입하지 않는다. "매퍼 밖·큐 위 변환" 어댑터 경계도 그대로다.

## 배경·근거 (왜)

M2 도그푸딩에서 후속 과제로 제기됐던 항목이다 (M2 플랜 "남은 것", PR #21 "담지 않은 것"). 재검토 결과 두 채널로 나뉜다:

1. **이벤트 flags 채널** — 소스 nil인 합성 `CGEvent`는 flags 기본값이 실행 시점의 실제 modifier 상태라 물리 Shift가 새어 들어간다. 이건 세션 A 구현부터 `KeyboardAdapter`가 keyDown·keyUp 모두에 `stroke.flags`를 명시 대입해 이미 막고 있었다 (빈 flags 포함 — 대입은 선택이 아니라 필수라는 주석과 함께).
2. **전역 상태 채널** — 이벤트 flags가 아니라 `NSEvent.modifierFlags`/`CGEventSource.flagsState` 같은 전역 modifier 상태를 별도로 읽는 앱. 2026-07-26 재현 도그푸딩(Notion·TextEdit, Shift를 꾹 누른 상태 유지 포함)에서 `$`·`G`·`A` 전부 **미재현** — 이동이 선택으로 변질되는 증상이 관찰되지 않았다.

전역 상태는 물리 키보드가 구동하는 값이라 합성 이벤트로 "정리"하려면 가짜 Shift keyUp/flags-changed를 게시했다가 복원하는 방법뿐인데, 이는 사용자가 실제로 누르고 있는 modifier 상태를 다른 앱·시스템이 오인하게 만들 수 있는 침습적 핵이다. 관찰된 증상 없이 도입할 근거가 없다.

## 검토한 대안

- **게시 전 전역 modifier 정리 (flags-changed 합성)**: 미재현 증상에 대한 침습적 핵 — 물리 Shift 상태를 시스템 전체가 오인할 위험이 이득보다 크다. 실증상이 발견되면 그 앱·증상 형태에 맞춰 재검토한다. 기각.
- **미재현이니 무기록 종결**: 플랜이 "어댑터 레벨이라 decisions 선행"으로 명시한 항목이라, 왜 코드 변경 없이 닫혔는지 기록이 없으면 다음 세션이 같은 우려를 다시 조사하게 된다. 기각.

## 영향 범위

- 코드 변경 없음 — `KeyboardAdapter.swift`의 기존 flags 대입이 결정의 구현체다.
- M2 플랜의 "Shift 새어 들어감" 항목 종결 근거.
- 재개 트리거: 전역 modifier 상태를 읽는 실제 앱에서 이동→선택 변질이 관찰되면 이 문서를 supersede하고 그 증상 형태에 맞춰 설계한다.
