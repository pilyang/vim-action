# Visual 후진·wise 재적용은 키보드 재앵커 시퀀스

## 결정

앵커 상태([협력자 결정](20260804_visual-anchor-state-collaborator.md))와 선택 범위 읽기가 뒷받침될 때, Visual의 후진 확장과 wise 재적용은 **재앵커 시퀀스**로 재조립한다: 선택을 앵커 반대쪽 끝으로 접은 뒤(`←`/`→` — 표준 macOS collapse) 위치 상대 스트로크로 다시 늘린다. **AX 쓰기는 도입하지 않는다** — 혼용(읽기 AX, 실행 키보드) 원칙 그대로다.

상태는 앱에 박힌 앵커가 논리 앵커 A의 어느 쪽 끝인지를 **side**로 추적한다(`.left` = 전진형 `[A, F+1)` / `.right` = 후진형 `[F, A+1)`). 재앵커는 **방향이 바뀌는 순간에만** 필요하다.

**핵심 관측 — 후진형에서는 원점 이동이 없다.** `vb` 빈 선택의 근원은 진입 `Shift-→`가 앱 포커스를 Vim 포커스보다 +1 앞세우는 것(inclusive의 대가)인데, 이는 **전진형에만 있는 오차**다. 후진형 `[F, A+1)`의 앱 포커스는 정확히 F라, 한 번 재앵커한 뒤의 연속 후진(`vbb`·`Vkk`)은 보정 없이 정확하다.

대표 시퀀스 (전부 위치 상대적 또는 상수 — [재조립 원칙](20260803_refinement-branches-not-stroke-counts.md) 유지):

| 케이스 | 시퀀스 | 결과 |
|---|---|---|
| `vh` (count n, 진입 직후) | `←, →` 재앵커 후 `Shift-← ×(n+1)` | Vim 동일 `[P−n, P+1)` |
| `vb` (진입 직후) | 재앵커 후 `Shift-Opt-←`, 캐럿이 단어 시작이면 ×2 (PR-B 단어 런 술어 재사용) | 이전 단어 + 커서 글자 |
| `Vk` (count n) | `←, ↓` 재앵커(앵커 줄 끝) 후 `Shift-↑ ×(n+1)` | 현재 줄 + 위 n줄, 개행 포함 |
| `Vgg` | 재앵커 후 `Shift-Cmd-↑` 1타 | 문서 시작 ~ 현재 줄 통째 (상수 1타) |
| `v`→`V` 앵커 반올림 | `←, Cmd-←`로 앵커를 줄 시작에 재수립 후 포커스 재확장 | 앵커 줄도 통째 포함 |

전진 확장이 앵커 위에서 출발하지 않는 경우(이미 늘어난 선택의 축소 등, Vim 목표가 여전히 앵커 앞쪽)는 재앵커 없이 현행 스트로크가 이미 맞다 — 재앵커 필요 여부는 읽은 선택 범위 + 카운트로 게시 전에 판별한다.

**수용 엣지 (신규) — 앵커 크로싱**: 한 모션이 앵커를 한 번에 넘는 경우(`.right`에서 전진 단어 모션 등)는 착지점을 앱만 알아 게시 전에 넘는지를 판정할 수 없다. 지금도 틀리는 케이스라 악화가 없고, Visual이라 화면에 보이며, Vim에서도 드문 조작이다. 도그푸딩 오인 금지 목록에 남긴다.

## 배경·근거 (왜)

키보드의 근본 제약은 "앱에 박힌 앵커 너머로는 Shift+모션이 선택을 못 만든다"였다([원점 이동 수용](20260728_visual-charwise-backward-origin-shift.md)). 그 문서의 "앵커를 옮겨도 포커스 출발점은 그대로라 상태로 넘을 수 없다"는 판정은 **앵커 오프셋을 모르는 무상태 전제**에서만 성립한다 — 앵커 A를 알고 현재 선택 `[l, r)`을 읽을 수 있으면, 접기(collapse)로 캐럿을 원하는 끝에 정확히 놓고 재확장할 수 있어 원점 이동 문제가 통째로 사라진다.

재앵커가 다른 수단보다 나은 이유:

1. **혼용 원칙 안에 머문다.** 쓰기의 비대칭 위험(빌드 순서 원칙)과 `AXError` 실패 보고 배선은 PR-D1의 몫이다 — C1은 읽기만 쓰므로 실패 = 폴백이라는 단일 계약이 유지된다.
2. **재조립 불변식이 그대로 성립한다.** 재앵커 접두는 상수 1~2타, 재확장은 카운트·줄 거리 비례(위치 상대) — 절대 오프셋 비례 스트로크가 없어 낡은 읽기의 최악이 현행을 넘지 않는다.
3. **폴백이 자연스럽다.** 상태 부재·읽기 실패·검증 실패 어느 쪽이든 현행 무상태 시퀀스로 강등된다(Slack·VS Code 상시 경로). 정확화 경로와 폴백 경로가 같은 매퍼 구조를 공유한다.

## 검토한 대안

- **`AXSelectedTextRange` 쓰기로 선택 설정 (오퍼레이터만 키보드)**: 크로싱까지 원리적으로 전부 풀리지만, 목표 범위를 오프셋으로 계산하려면 단어 경계·줄 이동·열 보존 등 모션 시맨틱을 우리가 재구현해야 한다 — 사실상 PR-D의 모션 엔진 조기 도입이고, 쓰기 실패 경로·실패 보고 배선도 함께 온다. C1 스코프 초과로 기각. D1에서 재료가 갖춰지면 그때 자연스럽다.
- **게시 후 재읽기로 크로싱 보정**: 모션 게시 → 결과 재읽기 → 교정 시퀀스 추가 게시. `CGEvent.post`는 비동기 배달이라 재읽기가 낡은 값을 볼 수 있어 대기/폴링이 필요해지고, "액션당 lazy 읽기 1회" 구조를 깬다. 기각 — 크로싱은 수용.
