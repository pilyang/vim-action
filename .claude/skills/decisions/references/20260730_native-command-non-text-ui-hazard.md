# 명령 어휘는 비텍스트 UI에서도 발사된다 — 단계 3까지 수용

> 이행 완료 — 비텍스트 걸러내기 게이트([20260801_non-text-filter-keeps-motion-and-scroll.md](20260801_non-text-filter-keeps-motion-and-scroll.md))가 구조적으로 해소해 수용 결정의 효력은 소진. Finder `p`/`u` 위험 분석은 재참조 가치로 파일 유지.

## 결정

새 명령 어휘(`o`/`O`·`p`/`P`·`u`/`Ctrl-r`)가 텍스트가 아닌 UI에서 **앱 수준 명령으로 발사되는 것**을 단계 3의 요소 리졸버까지 **수용**한다. 코드로 막지 않는다. 대신 **도그푸딩 규율을 확대**한다: 스크래치 문서뿐 아니라 **스크래치 폴더**에서만, Finder·Mail 등 문서 앱에서는 의도적으로만 시험한다.

## 배경·근거 (왜)

`family`는 단계 3의 `focusedRole` 리졸버가 붙을 때까지 어댑터가 `.textArea`로 고정 주입한다([편집 매핑 계약](20260727_edit-keystroke-mapping-contract.md)). 단계 1·2까지는 이 고정의 대가가 작았다 — 텍스트가 아닌 곳에서 모션은 화살표라 무해하게 흘러가고, `Cmd-X`는 대개 미바인딩이다. **명령 어휘는 그 성질이 없다.** 이 다섯은 정의상 "앱이 이미 아는 명령"이라, 포커스가 무엇이든 그 앱에서 의미를 갖는다:

- **Finder**: `p`=`Cmd-V`는 **현재 폴더에 파일을 붙여넣고**, `u`=`Cmd-Z`는 **직전 파일 조작을 되돌린다**(옮긴 파일 되돌리기, 휴지통 복원). `o`는 `Cmd-→, Return`이라 이름 변경/열기를 건드린다.
- **문서 앱 일반(Mail·Photos 등)**: `u`가 **VimAction이 개입하기도 전에 사용자가 한 임의의 동작**을 취소한다.

즉 위험이 "텍스트 필드 안에서 키 시퀀스가 어긋난다"에서 "임의의 UI에 앱 명령이 발사된다"로 등급이 올라간다. 그래도 코드로 막지 않는 이유는 셋이다:

1. **막을 정보가 없다.** family가 하나뿐인 상태에서 "여기는 텍스트가 아니다"를 알 방법이 없다 — 그걸 아는 것이 정확히 단계 3 리졸버(`focusedRole`)의 일이고, 리졸버가 붙으면 비텍스트 계열에서 `nil`(정직한 스킵)이 구조적 해소다.
2. **사용자 노출이 없다.** 릴리스 배포 금지 게이트가 여전히 유효하다([게이트 M3 이동](20260726_release-block-gate-moves-to-m3.md)) — 지금 이 위험을 감당하는 사람은 도그푸딩하는 개발자 본인뿐이다. 그래서 답이 코드 가드가 아니라 **도그푸딩 규율**이다.
3. **임시 가드는 리졸버와 충돌한다.** 앱 축의 차단 목록을 급조하면 단계 3에서 두 개의 게이트를 정리해야 하고, 앱 게이트는 이미 다른 의미론(엔진 진입 전 통과)을 갖고 있다([M2 앱 게이트](20260726_m2-app-gate-pre-engine-passthrough.md)).

**규율 확대의 구체적 내용**: 기존 "래치 전까지 실문서 대신 스크래치 문서, 큰 카운트 자제"에 **"파일 조작이 걸린 앱(Finder 등)에서는 스크래치 폴더에서만"** 을 더한다. 되돌릴 수 없는 파일 조작이 `u` 한 번으로 일어날 수 있기 때문이다.

## 검토한 대안

- **앱 축 임시 차단 목록**: 단계 3 리졸버와 이중 게이트가 되고 앱 게이트의 기존 의미론과 충돌 — 기각.
- **명령 어휘를 단계 3 뒤로 미루기**: 그러면 v1 어휘가 계속 "죽은 키"로 남아 단계 4 게이트 해제 자체가 불가능하고, 단계 3의 실기기 검증은 오히려 실행되는 어휘가 있어야 의미가 있다 — 기각.
