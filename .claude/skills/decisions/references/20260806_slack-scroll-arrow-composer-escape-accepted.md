# Slack 스크롤 화살표의 컴포저 이탈은 Slack 기본 동작 — 별도 처리 없이 수용

## 결정

Slack에서 스크롤(`Ctrl-u`/`Ctrl-b` 등)의 `↑` 반복이 컴포저를 벗어나 **위에 올라가 있는
메시지 선택으로 넘어가는 동작**은 별도 처리 없이 수용한다 (사용자 확인 — PR-C2 세션 2
도그푸딩). 버그로 오인 금지: 우리 합성 화살표에 대한 **Slack 자신의 기본 키보드 동작**이다.

## 배경·근거 (왜)

- Slack은 포커스 요소를 노출하지 않아 뷰포트 읽기가 원리적으로 실패하고, 스크롤은 상수
  15/30의 무상태 폴백(화살표 반복)이다. 컴포저 캐럿이 첫 줄에서 포화한 뒤의 `↑`를 Slack이
  "메시지 목록 탐색/마지막 메시지 편집"으로 해석하는 것은 손으로 `↑`를 눌러도 같은
  네이티브 동작이다 — 우리가 만든 오동작이 아니다.
- 화살표는 비파괴적이라 실패 비용이 낮고(선택이 옮겨갈 뿐), 회피하려면 앱 축 특례가
  필요한데 그 수단은 이미 M4 프로파일로 존재한다(`profiles/com.tinyspeck.slackmacgap.yaml`에
  `scroll: disabled` 또는 모션 재정의) — 코드 특례를 더하는 것보다 단순하다.

## 검토한 대안

- **번들 Slack 프로파일에 `scroll: disabled` 추가**: 스크롤 어휘가 통째로 죽는다 — 채널
  본문 스크롤 용도(걸러내기 표에서 `.nonText`도 게시하는 이유)까지 잃는다. 기각.
- **Slack 전용 시퀀스/가드**: 앱 축 특례는 프로파일 몫이라는 M4 원칙 위반. 기각.

## 영향 범위

- 코드 무변경. 도그푸딩 시 버그로 오인 금지 항목.
- 사용자가 실사용에서 아프면 자기 프로파일로 조절하는 것이 공식 경로다.
