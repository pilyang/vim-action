# 삽입 하이브리드(`o`/`O`·`p`/`P`)에도 되읽어 검증을 건다 — default-deny 승계

## 결정

[되읽어 검증 수렴 폴링](20260808_ax-readback-verify-convergence-poll.md)의 문언은 파괴적 편집(파괴 단계 게시 전 선택 착지 확인)을 기준으로 쓰였지만, **접두가 캐럿 이동뿐인 `.openLine`·`.paste` 하이브리드에도 그대로 적용한다.** 하이브리드면 무조건 검증하는 세션 2 구현(default-deny)을 액션별로 가르지 않는다. 조절값(간격 2ms·상한 40ms)도 공유한다.

## 배경·근거 (왜)

- **위험 등급이 낮다는 것은 "위험이 없다"가 아니다.** 접두가 착지하지 않은 채 위임 그룹이 나가면 낡은 캐럿 위에서 터진다: `p`는 엉뚱한 자리에 텍스트를 삽입하고, `.appendingLine`의 `Return`은 **줄을 쪼갠다**. 둘 다 사용자가 undo로 되돌려야 하는 결과이며, 검증이 막는 것은 정확히 이 창이다.
- **비용에 상한이 있다.** 첫 재읽기는 지연 없이 나가므로 즉시 일관한 앱(TextEdit 실측)에서는 폴링 비용이 0이고, 비동기 적용 앱(Notion ~10ms 실측)에서만 수렴까지 기다린다. 상한 40ms는 이미 정해진 값이다.
- **규칙을 액션별로 가르면 표가 된다.** [하이브리드 접두+첫 그룹 원자](20260808_hybrid-prefix-atomic-with-first-group.md)가 "위험 등급이 낮은 paste·openLine까지 같은 규칙인 것은 감사 가능성 때문 — 규칙이 액션별로 갈리면 넷째 항이 표가 되고 얻는 것은 반응성 몇 ms뿐"이라고 이미 같은 논거로 결론지었다. 그 결정과 이 결정이 갈리면 하이브리드의 안전 규칙이 두 개의 서로 다른 축을 갖게 된다.
- 실패 시 처리도 그대로다 — 무동작 + execute 잔여 중단 + 전용 버킷 상시 `.info`(보고 아님, 쓰기는 `.success`였고 삽입은 시도 전).

## 검토한 대안

- **삽입 하이브리드는 검증 생략**: 접두가 비파괴라 "최악이 캐럿만 움직임"이라는 주장이 근거인데, **위임 그룹이 뒤따르는 순간 그 주장이 무너진다** — 검증 없는 접두 + 게시는 "낡은 자리에서 삽입"이라 비파괴가 아니다. (검증 없이도 안전한 것은 뒤에 아무것도 게시하지 않는 `.ax` 캐럿 모션뿐이고, 그쪽은 지금도 검증하지 않는다.)
- **삽입만 상한을 줄여 절충**: 상한이 두 개가 되고, 어느 쪽이 헛스킵을 만드는지 도그푸딩 로그로 가르기 어려워진다 — 조절값이 하나여야 관측 데이터가 하나다.

## 영향 범위

- 갱신한 architecture reference: [strategy-dispatch.md](../../architecture/references/strategy-dispatch.md) (되읽어 검증 문단의 적용 범위)

- 도그푸딩 관측: 되읽어 검증 불일치 `.info` 버킷에 이제 `p`·`o`도 들어올 수 있다. 삽입에서만 빈발하면 그때 이 결정을 재심사한다.
