# 하이브리드의 "AX 접두 쓰기 + 첫 게시 그룹"은 원자 — 사이 중단 질의 없음

## 결정

하이브리드 액션(편집·`.openLine`·`.paste`) 전부에서 **AX 접두 쓰기(및 되읽어 검증)와 첫 게시 그룹 사이에는 중단 래치 질의를 두지 않는다** — 원자 그룹 경계 규칙의 넷째 항이다. 쓰기 **직전**의 래치 질의는 유지한다(그 시점 중단은 아무 부수효과 없이 끝난다). CGEvent 생성 실패의 all-or-nothing도 같은 경계를 따른다 — 첫 그룹을 만들 수 없으면 접두 쓰기 자체를 하지 않는다(생성을 쓰기 앞으로 당긴다).

## 배경·근거 (왜)

- **편집 하이브리드의 사이 중단은 살아 있는 선택을 남긴다.** AX 범위 선택이 착지한 뒤 `Cmd-X`/`Cmd-C`가 안 나가면 화면에 선택이 잔류하고, 다음 Normal `x`(`Shift-→, Cmd-X`)가 그것을 통째로 잘라낸다 — 원자 그룹 ②(`.edit(_, .selection)`과 `clearSelection` 사이)가 막는 것과 정확히 같은 축의 위험이다. keyboard 편집은 선택+오퍼레이터가 한 그룹이라 이 창이 없었고, 하이브리드는 쓰기와 게시가 두 단계라 규칙 없이는 창이 새로 열린다.
- **기존 규칙의 연장이라 새 개념이 아니다.** 원자 그룹 ③("`.paste`의 접두 + 첫 `Cmd-V`")의 문언이 접두를 AX 쓰기로 바꿔도 그대로 성립한다 — "접두만 실행되고 끊기면 조용한 오동작"이라는 근거가 동일하다(`Return`만 나가는 openLine = 빈 줄, 캐럿만 옮긴 paste = 위치 이동).
- **잃는 반응성은 기존 수용 규모다.** 사이 질의를 빼서 더 나가는 것은 1타 게시 그룹 하나(오퍼레이터/`Cmd-V`/`Return`) 분이다 — 중단 래치 설계가 이미 수용한 "무효화 순간의 in-flight 꼬리 ≤ 1 스트로크"와 같은 규모이고, AX 경로의 질의 지점(액션 사이 + 쓰기 직전)은 keyboard 8타 청크보다 여전히 촘촘하다.
- 위험 등급이 낮은 paste·openLine(접두가 캐럿 이동뿐)까지 같은 규칙인 것은 감사 가능성 때문이다 — 규칙이 액션별로 갈리면 넷째 항이 표가 되고, 얻는 것은 반응성 몇 ms뿐이다.

## 검토한 대안

- **편집만 원자, paste·openLine은 사이 질의 허용**: 위험 등급별 최적이지만 규칙 분기 대비 이득(1타 분 반응성)이 없다.
- **사이 질의 허용 + 중단 시 보정 게시**(선택 collapse 등): 중단 경로가 새 게시를 만든다 — 중단의 의미("잔여 폐기")를 스스로 깬다.
